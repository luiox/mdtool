
为了彻底解决markdown的图片和附件管理混乱的问题，定义此规范
因为是本地，所以ip选127.0.0.1，然后typora要求服务器是8765端口，所以我们的图片和附件管理服务器也是这个端口。
那么图片链接为下面这个格式，其中alt位置的这个img，可以为具体的图片名字，即图片说明。alt标签必须在链接转换过程中原始保留。

```markdown
![img](http://127.0.0.1:8765/images/image-YYYYMMDDHHMMSSnnn.*)
```

具体举例为

```markdown
![测试图片](http://127.0.0.1:8765/images/image-20201215174726729.png)
```

然后附件统一都放在assets这个url下。例如。

```markdown
[测试pdf文件](http://127.0.0.1:8765/assets/YYYYMMDDHHMMSSnnn.pdf)
[测试zip文件](http://127.0.0.1:8765/assets/YYYYMMDDHHMMSSnnn.zip)
[测试drawio文件](http://127.0.0.1:8765/assets/YYYYMMDDHHMMSSnnn.drawio)
```

对于mdtool的附件服务器跟图床服务器共用一个端口，对于附件的访问，例如http://127.0.0.1:8765/assets/YYYYMMDDHHMMSSnnn.pdf，那在浏览器中请求时候，应该设置为原始文件名，附件服务器需要维护一个元信息表。可以用下面这样子的方式，设置Content实现。

```
Content-Type: application/pdf
Content-Disposition: attachment; filename*=UTF-8''用户手册.pdf
```

对于mdtool的服务器，设计为使用sqlite管理元信息，统一用一个`meta.db`文件，内部一个image表，一个assets表。
针对image表，表结构定义如下

```sql
CREATE TABLE images (
    timestamp_name TEXT PRIMARY KEY,   -- 例如 "image-YYYYMMDDHHMMSSnnn.png"
    original_name TEXT NOT NULL,       -- 原始文件名 "截图.png"
    size INTEGER NOT NULL,             -- 文件大小（字节）
    mime TEXT NOT NULL,                -- 例如 "image/png"
    upload_time TEXT NOT NULL          -- ISO 8601 时间戳，例如 "2025-03-15T14:30:22Z"
);
CREATE INDEX idx_images_original ON images(original_name);
CREATE INDEX idx_images_upload_time ON images(upload_time);
```

针对assets表，表结构定义如下

```sql
CREATE TABLE assets (
    timestamp_name TEXT PRIMARY KEY,   -- 例如 "YYYYMMDDHHMMSSnnn.pdf"
    original_name TEXT NOT NULL,       -- 原始文件名 "用户手册.pdf"
    size INTEGER NOT NULL,
    mime TEXT NOT NULL,                -- 例如 "application/pdf"
    upload_time TEXT NOT NULL
);
CREATE INDEX idx_assets_original ON assets(original_name);
CREATE INDEX idx_assets_upload_time ON assets(upload_time);
```

然后本地的服务器就需要设置一个根目录，然后下面分别建立`assets`和`images`目录，全部扁平化存放，根目录内存这个`meta.db`数据库。

图片和附件都可以在mdtool内上传至服务器，并且随时可以查询某个图片或者附件的url应该是什么，仅需输入名字，应该支持正则表达式的名字查找。
图片和附件不一样的地方在于，图片额外支持由typora调用`typora-uploader`上传。
