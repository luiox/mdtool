# 博客文章管理规划（v1，2026-08-29）

## 1. 背景与痛点

博客源：Hexo 站点（源码仓与产物仓分离；源码仓私有，名字与本地落位不写入本公共仓库）。现状：

- 文章在 `source/_posts/*.md`（当前 26 篇），图片平铺在 `source/assets/`，正文用**相对路径**引用：`![x](assets/xxx.png)`。
- 全流程纯手工：新建文章、front-matter 抄模板、图片手工放进 assets、链接手敲、失效了肉眼排查。hexo-admin（`hexo server -d`）只解决"新建文件"这一步，图片与链接完全不管。
- 图片链接一多就是灾难：文件名对不上、图片进了仓库但链接写错、删了图片链接残留，全靠人工核对。

目标：**把博客源目录当作 mdtool 的一种知识库形态接管**，文章与图片的增、查、校验、发布辅助全部工具化。

## 2. 与现有架构的关系

- **编辑器仍由 Typora 专职**，mdtool 不做编辑（同知识库主流程的分工）。
- **复用现有能力**：图片校验（AST/正则解析）、`libmarkdown` 幂等 AST 读写、文件浏览器、`link_resolver.py` 的目标制改写。
- **链接模型的豁免**：[知识库规范](知识库规范.md) 将"存储改相对路径"否决为**知识库默认**（理由：笔记任意深度时相对路径按深度计算、移动即断链）。博客形态是**有正当理由的例外**：
  - 博客的消费方是 GitHub Pages 静态托管，本地图床 `http://127.0.0.1:8765/...` 对读者不可达，图片必须进仓库、必须相对引用；
  - Hexo 的 `_posts` 是**单层平铺**，不存在"任意深度"问题，相对路径固定为 `assets/<name>`，不会触发规范否决时担心的断链场景。
  - 落地方式：给 `link_resolver.py` 增加 `hexo` 目标（解析 `assets/<basename>` 相对链接），与既有 `zip` 目标并列。**豁免只对博客形态生效，不回渗到知识库默认模型。**

## 3. 分阶段功能

### B0 博客源识别（地基）

- 把含 `_config.yml` + `source/_posts/` 的目录识别为"博客源"，作为文件浏览器的一种数据源（与散装/db 模式并列）。
- 文章列表读 front-matter（标题/日期/categories/tags），按日期排序展示。
- **验收**：打开博客源目录，26 篇文章列表与 front-matter 元数据正确显示。

### B1 新建文章脚手架

- 按 Hexo `scaffolds/post.md` 模板生成新文章，自动填 title/date/filename，替代手工+hexo-admin。
- **验收**：mdtool 新建一篇文章 → `hexo server` 下可见且元数据完整。

### B2 图片闭环（本规划的核心价值）

- **插入图片**：选择/粘贴图片 → 自动按现有命名规则存入 `source/assets/` → 在光标处插入相对链接 `![](assets/<name>)`。
- **校验**：复用图片校验遍历 `_posts` 全量链接，报告：assets 文件不存在、图片无引用（可清）、链接格式异常。
- **迁移**：散落在文章目录的图片一键迁入 `assets/` 并批量改写链接（复用 migrate 能力，目标 `hexo`）。
- **验收**：对现有 26 篇跑一次全量校验，输出的报告与人工核对结果一致；插入一张新图到一篇文章，hexo 渲染可见。

### B3 发布辅助

- 命令面板封装 `hexo clean / generate / server -d / deploy`（subprocess，输出回显）。
- **验收**：mdtool 内完成"写文章 → 插图 → 校验 → 生成预览"全流程，不碰命令行。

## 4. 明确不做

- 不做 Markdown 编辑器（Typora 专职不变）。
- 不接管 Hexo 主题、构建配置、评论系统。
- 不改动知识库默认的图床 URL 模型；`hexo` 相对路径目标是独立分支，不混用。
- 不做多人协作/草稿审阅（个人博客，无此需求）。

**博客仓魔改配套（博客源仓本地检出，2026-08-31）**

- **索引相对路径加固**：`generate_passage_index.js` 统一存仓库相对路径（posix+NFC），
  加载时把存量绝对路径原位迁移（id 不变；已迁移 27 条并核对 id 映射逐一相等）；
  `set_permalink_by_index.js` 候选同时给绝对/相对形式（兼容旧索引），并为非文章对象
  加守卫消掉归档/标签路过钩子的日志噪音。**纪律：已发布文章不改文件名（改名 = 换 URL）。**
- **首建时序修复**：原脚本索引在 `before_generate`（文件处理之后）才跑，新文章首次
  build 匹配不到索引、permalink 先落随机串、二次 build 才变数字 id（URL 首发即变，
  即 git log 里"修复最新文章链接解析错误"那类问题的根因）。修复为插件**加载期**
  同步先跑索引脚本；临时笔记库全链路实测：新建文章首次 build 即得 `article/28.html`。
- **发布链路修复**：`npm install hexo-deployer-git`（原 `_config.yml` 的 git deploy
  配置因缺插件不可用）；`package.json`/`package-lock.json` 虽列于 .gitignore 但实际
  被 git 跟踪，依赖随仓库提交。
- **全链路实测**（临时笔记库 → 抽取 → generate → 预览）：图床 URL 与相对图片两种
  链接均正确改写入 `assets/`，外链保留；clean 重建 27 篇分配id 全中；`hexo server`
  下文章页与图片均 200。测试产物已清理、索引已还原。

**与原规划的偏差（记录在案）**

- **UI 形态**：原计划"作为文件浏览器的一种数据源"，落地为独立博客页 + 顶栏第三数据源按钮。理由：文章列表需要五列 front-matter 元数据表格（库树只有文件名列），且不动 library 页 fs/db 双模式的既有编排。
- **"在光标处插入"**：mdtool 不做编辑（Typora 专职约束），导入图片后链接写入剪贴板，由用户在 Typora 光标处粘贴。
- **校验判定边界**：图床 URL 判为问题（静态托管不可达）；无后缀的相对链接（Hexo permalink 形态）与文章互链不判，避免误报。
- **resolver 双端同步**：`hexo` 目标仅桌面管理侧实现，手机端 `LinkResolver.kt` 无此语义（手机只读知识库，不消费博客形态）——豁免不回渗知识库默认模型。

## 7. 阶段 1 落地：sitegen 自研生成器（feature/sitegen 分支，2026-09-06）

目标形态：**Hexo 整体退役**——文章活在笔记库（`blog/` 文件夹或任意笔记勾选），
发布清单是一个 manifest JSON（`next_id` + note→id，id 只增不改永不复用，
存量 `passage_index.json` 的 28 个 id 平移进来保证老 URL 全存活），渲染/生成
由 mdtool 自产，产物直接推 luiox.github.io 产物仓。模板基调对齐 jacman 视觉
（#2ca6cb 实心 header、灰底白卡、正文右上角浮动 TOC 小卡片、代码块复制按钮、
图片灯箱），范本为 mouse0w0.github.io（jacman 系）实测计算样式。

- **新增**：`mdtool/core/sitegen/`（manifest/render/generate/legacy 纯函数层 +
  templates/static 数据目录，`resource_dir()` 兼容 frozen 态）、
  `scripts/sitegen_check.py`（对 hexo public/ 的对齐验证，阶段 2 回归可用）。
  新依赖：markdown-it-py / mdit-py-plugins / jinja2 / pygments（全纯 Python）。
- **对齐验证**（sitegen_check，2026-09-06）：文章 id 集合与 hexo 产物一致、
  title 逐一相等、站内链接/页内锚点全可达、assets 媒体全覆盖、零跳过。
  个别清单条目的文件已删除但 id 保留，预期语义（URL 身份归历史）。
- **渲染语义三铁律**（反查 hexo public/ 得到）：`assets/x` 相对链接 → 根绝对
  `/assets/x`（编码交给 markdown-it normalizeLink，自己预编码会双重编码成
  %25）；`<a>` 的属性在 `link_open` token 上（不是 "link"）；外链加
  target=_blank rel=noopener（hexo external_link 同款）。
- **宽容 front-matter**：hexo-admin 时代的存量文章有缺 opening `---` 的形态
  （hexo 容忍），sitegen `_split_meta` 对齐之，meta 不再漏进正文（3 篇受影响
  已验证）；另外把 `hello-world.md` 数据修正补上了 opening 栅栏（对 hexo 无感）。
- **与 hexo 的行为差异（有意）**：TOC 用 anchors 插件（slug 保留 CJK，锚点
  文本与 hexo 略异）；代码高亮 Pygments friendly（原 highlight.js）；无 jQuery/
  fancybox，复制按钮与灯箱为原生 JS 重写；分类页保留、标签页含云图。
- **阶段 2 已落地（2026-09-06，同分支）**：博客页新增 sitegen 行——「生成站点」
  （输出 `public-sitegen/`，与 hexo 的 `public/` 隔离，博客仓 .gitignore 已
  收录）、「发布站点」（生成 + git 直推产物仓；部署克隆 `.deploy_git-sitegen/`
  落在既有 `.deploy*/` 忽略规则内，无变更自动跳过 push，替代 hexo-deployer-git，
  提交身份沿用 git 全局配置）、「预览站点」（内置 stdlib 线程服务器

  独立 python 子解释器，`npm run server` 方案不可移植）。hexo 行保留作回退。
  新增 `sitegen/deploy.py`（计划/执行分离，git 流程用本地 bare 仓真实测试）。
  阶段 2 的 id 事实源仍是博客仓 passage_index.json（legacy 适配器直读），
  桌面端不另落 manifest。
- **视觉对齐定稿（2026-09-06，同分支）**：首版照 mouse0w0.github.io 截图模仿
  踩坑——把全站塞进 960px 居中窄栏，而原版 jacman 是大容器双栏。返工基准改
  为两处一手事实：博客源仓 theme 未改状态的历史版本（读 archive/sidebar EJS 与
  index/aside styl）+ 线上 luiox.github.io 实测计算样式。定稿骨架：全局容器
