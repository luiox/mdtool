# 博客撰写与发布工作流

> **主通道 = sitegen 自研生成器**：文章活在笔记库（博客目录 B），勾选制
> 发布，渲染/生成由 mdtool 自产，git 直推产物仓 `luiox.github.io`；hexo
> 通道（Hexo 7 + jacman 魔改主题，源码仓私有）保留作**回退**，跑稳后退役。
> 本文是**操作流程的权威定义**；功能设计见 [博客文章管理规划.md](博客文章管理规划.md)，
> 主题/外观定制契约见 [博客主题定制.md](博客主题定制.md)。

## 1. 角色分工（KB 形态 · 主通道）

| 环节 | 谁 | 说明 |
| --- | --- | --- |
| 写作/编辑 | Typora | 专职编辑，mdtool 不做编辑；文章就是笔记库里被勾选的 `.md` |
| 文章元数据/列表 | mdtool 博客页 | front-matter 五列表格；发布范围 = manifest 勾选 |
| 勾选发布范围 | mdtool「选择发布文章」 | 复选树勾笔记/文件夹 → `manifest.json`；id 只增不改（URL 身份） |
| 插图 | mdtool「导入图片」 | 拷入 `B/assets/`（时间戳命名），链接上剪贴板，Typora 光标粘贴 |
| 校验 | mdtool「校验全库」 | 失效链接 / 散落媒体 / 图床 URL / 无引用 assets |
| 渲染 + permalink | sitegen | 「生成站点」→ `B/public-sitegen/`；id 来自 manifest，`article/<id>.html` 永久稳定 |
| 发布 | mdtool「发布站点」 | 生成 + git 直推产物仓（目标在 `B/site.json` 的 deploy 键） |
| 预览 | mdtool「预览站点」 | 内置 stdlib 服务器（端口自动分配，随应用退出停止） |
| 外观/主题 | `B/theme/` | 模板/静态逐文件覆盖默认主题，契约见 [博客主题定制.md](博客主题定制.md) |

### 回退通道（hexo，退役前维持可用）

hexo 源仓的对应动作：渲染/发布 = mdtool 博客页 hexo 行（`npm run build` +
`npm run deploy`）、预览 = `npm run server`（<http://localhost:4000>）、
permalink 由魔改索引钩子分配。纪律与魔改备忘见 §4（对两通道同样有效，
id 语义已随迁移平移进 `manifest.json`）。

## 2. 撰写回路（日常）

**主路径（KB 形态）：**

笔记库里写到成文 → mdtool 博客页「选择发布文章」勾选（确认即落
manifest；新文章自动分新 id）→ 需要插图时 mdtool「导入图片…」（链接进
剪贴板，Typora 粘贴）→ 发布/预览。文章语气润色直接在笔记里做，不需要
"抽取/搬移"步骤。

**回退路径（hexo 时代，两条）：**

- **A. 直接写**：hexo 形态博客页「新建文章…」（读博客仓 `scaffolds/post.md`
  模板）→ Typora 写 → 「导入图片…」。
- **B. 从笔记库抽取**：hexo 形态博客页「从笔记库导入…」→ 图床 URL 改写
  为 `assets/<名>`、图片拷入 `source/assets/` → Typora 润色。

**纪律（URL 身份 = manifest 里的 id，改前必读）：**

1. **勾选事实与 id 都在 `manifest.json`**（随笔记库走）：取消勾选仅
   `selected=False`，id 永不回收；重勾 id 不变、老 URL 全存活。**不要手工
   编辑 manifest 的 id/note 字段**。
2. 已发布的文章改路径 = manifest 键失配（生成报"失联"），重命名前先想
   清楚 URL 是否要跟着断。
3. 图片一律走「导入图片」进 `B/assets/`，正文用 `assets/<名>` 相对链接
   （sitegen 生成时根绝对化），不手放文章旁。
4. 草稿 = 未勾选的笔记，没有独立目录；hexo 形态才有 `_drafts/` 语义。

## 3. 发布回路

```
写完 → mdtool「校验全库」（零失效链接）→ 勾选发布范围 → 「发布站点」
       = sitegen 生成（B/public-sitegen/）
       + git 直推 B/site.json 的 deploy.repo（.deploy_git-sitegen/ 克隆，
         无变更自动跳过 push）
```

- 首次发布前手填 `B/site.json` 的 `deploy.repo`（迁移时自动从 hexo
  `_config.yml` 提取，一般无需再动）；产物仓提交人 = git 全局配置身份。
- 生成报告在日志页逐行回显：文章数/文件数/跳过清单（单篇坏不拖垮整站）。
- 发布后开 <https://luiox.github.io> 验证；日常核对用「预览站点」。
- 回退通道：hexo 行「一键发布」（`hexo generate` + `hexo deploy`）、
  「清理缓存」（`hexo clean`）照旧可用。

## 4. 博客仓魔改备忘（mdtool 不碰的部分）

- `generate_passage_index.js`：为 `_posts/*.md` 维护 `{path → id}` 索引，**只增不改**
  （存量 id 永不复用/重排）；`scripts/set_permalink_by_index.js` 的钩子强制
  `article/<id>.html`。索引在 hexo 插件**加载期**同步生成（`before_generate` 仅兜底）：
  保证新文章首次 build 就拿到稳定数字 id——此前索引在文件处理之后才跑，新文章首发
  permalink 会先落到随机串、二次 build 才变数字 id（URL 首发即变的缺陷，2026-08-31 修复）。
- `passage_index.json` 存仓库相对路径（2026-08-31 迁移完成，id 映射逐一核对不变），
  随仓库提交，换机器不断链。
- jacman 主题与 `_config.yml`（含 `permalink: article/:id.html`）维持手工维护，
  mdtool 不接管主题/构建配置。
- `package.json`/`package-lock.json` 被 git 跟踪（虽曾列于 .gitignore，规则已删）；
  发布依赖 `hexo-deployer-git`（2026-08-31 安装，此前 `hexo deploy` 因缺插件不可用）。

## 7. mdtool 设施 ↔ 流程对照

| 流程动作 | mdtool 入口 | 内核 |
| --- | --- | --- |
| 识别/列表/校验/迁移/新建/插图 | 顶栏「博客源」→ 博客页 | `mdtool/core/blog.py` 纯函数 |
| 从笔记库导入（hexo 形态） | 博客页「从笔记库导入…」 | `blog.plan_note_extract / apply_note_extract` |
| 勾选发布范围（KB 形态） | 博客页「选择发布文章」 | `sitegen/manifest.apply_selection`（id 只增不改） |
| 生成/发布/预览站点（双形态共用按钮） | 博客页 sitegen 行 | `sitegen/generate.build_site` + `sitegen/deploy` + `sitegen/preview` |
| 一键发布/预览/清理（hexo 回退） | 博客页 hexo 行 | `_hexo_job`（subprocess，输出回显日志页） |
| 链接语义 | `hexo` resolver 目标 | `link_resolver.rewrite(target="hexo")`，仅桌面侧 |
| 外观定制 | `B/theme/` 覆盖包内默认主题 | 契约见 [博客主题定制.md](博客主题定制.md) |
