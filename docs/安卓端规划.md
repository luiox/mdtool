# 安卓端规划（v1，只读浏览）

> 状态：已确认进入开发。配套：`docs/定位与架构分析.md`（决策依据）、`docs/知识库规范.md`（KB 根布局与链接分层）。

## 1. 定位（已确认）

- 原生安卓 app（**Kotlin + Jetpack Compose**），**只读浏览端**。
- **不做同步**：用户用第三方同步 app（Syncthing / 坚果云 / OneDrive 等）把知识库文件夹同步到手机，然后在本 app 里用系统文件选择器（SAF）**选择该文件夹**即可。
- **核心机制**：app 内置本地 HTTP 服务器（固定 `127.0.0.1:8765`，与桌面端一致）→ 笔记里存储的 `http://127.0.0.1:8765/...` 链接在手机上**原样可解析**（同端口零改写）；正文经服务器渲染后由 WebView 展示。

## 2. 架构

```
MainActivity（Compose）
├── 文件夹选择     SAF ACTION_OPEN_DOCUMENT_TREE + 持久授权（takePersistableUriPermission）
├── 笔记树         DocumentFile 遍历 <kb>/notes/**
├── 搜索           端上遍历 + 正则/子串匹配（个人 KB 规模够快；预留 FTS5 升级路径）
└── 阅读页         WebView ← http://127.0.0.1:8765/note/<path>
        └── 本地服务器（NanoHTTPD）
            ├── /note/<path>     flexmark 渲染 md→HTML（含 link resolver 改写）
            ├── /images/<name>   静态媒体（DocumentFile 流式读取，Content-Type 映射）
            ├── /assets/<name>   同上 + Content-Disposition 原始名（查 meta.db，缺失降级）
            └── /search          JSON 搜索接口（备选；端上遍历为主）
```

**关键设计点**

| 点 | 决策 |
| --- | --- |
| 端口 | 固定 `8765`（与桌面 Typora/媒体服务器一致）→ 存量链接零改写；若笔记中 host/port 与本地不一致（如自定义端口），按规范 §2 由 resolver 改写为 `http://127.0.0.1:8765/...` |
| cleartext | WebView 需允许 http 明文：`android:usesCleartextTraffic="true"`（或 network security config 仅放行 127.0.0.1） |
| 渲染 | flexmark（JVM 生态成熟，GFM 表格/删除线/任务列表）；服务端渲染与桌面导出共用"渲染/改写语义"（resolver 两端同语义） |
| 附件原始名 | KB 根含 `meta.db` 时读取（Android 原生 SQLite）；缺失则按时间戳名下载（降级） |
| resolver | Kotlin 实现 `parse`/`rewrite`（desktop/zip/phone 语义与 `mdtool/core/link_resolver.py` 一致） |
| 搜索 | 端上协程遍历 + 正则（文件名/正文）；中文无分词问题，个人规模毫秒级 |

## 3. 工程结构

```
android/
├── settings.gradle.kts / build.gradle.kts / gradle.properties
├── gradle/libs.versions.toml         # 版本目录（AGP/Kotlin/Compose BOM）
└── app/
    ├── build.gradle.kts
    └── src/main/
        ├── AndroidManifest.xml
        └── java/com/mdtool/android/
            ├── MainActivity.kt        # Compose 入口 + 文件夹选择
            ├── ui/                    # 界面：树 / 搜索 / 阅读 / 主题
            ├── kb/KbRepository.kt     # DocumentFile 遍历与读取
            ├── server/LocalServer.kt  # NanoHTTPD 路由
            ├── render/MarkdownRenderer.kt  # flexmark + 自定义 HTML
            └── resolver/LinkResolver.kt    # 与桌面 link_resolver 同语义
```

## 4. 构建与验证（已完成）

- **已本地验证**：本机 SDK（`D:\sdk\AndroidSdk`）+ JDK 17 + Gradle 8.10.2（wrapper）→ `./gradlew :app:assembleDebug` **BUILD SUCCESSFUL**，产出 `app-debug.apk`（约 16 MB）。
- 期间修复：`DocumentFile` 无 `openInputStream()`（改用 `ContentResolver`）、`const val` 不能为 `Set`、类私有成员跨顶层函数不可见、flexmark-all 引入 openhtmltopdf 导致 license 打包冲突（改用 flexmark 按需模块 + packaging excludes）。
- **国内网络**：`settings.gradle.kts` 内置阿里云镜像兜底；gradle 发行版走腾讯镜像（见 `android/README.md`）。
- 真机安装验证（选文件夹 → 浏览/搜索/渲染）仍待用户在真机上执行。

## 5. 明确不做（v1）

- 任何同步逻辑（第三方 app 负责）
- 服务器地址配置 UI（固定 127.0.0.1:8765，代码常量可改）

## 6. 同批桌面端收尾（P1 待办）

1. **多篇/全库 zip 导出**：文件浏览器支持多选（`ExtendedSelection`）+ 右键"打包为 ZIP（N 篇）"；zip 内保持笔记相对目录结构，媒体平铺 `images/`/`assets/`，链接按笔记深度加 `../` 前缀改写（`plan_zip_bundle` 增加 depth 参数）。
2. **散装搜索**：文件浏览器（KB 视图）加正则搜索栏（文件名/正文/两者），直接扫文件、不依赖 db（搜索从 notes.db 迁移到文件扫描；个人规模不建索引缓存）。
3. **一键"散装 → db 包"**：文件浏览器右键"导出为 db 包"（复用笔记库的导入 job），补全"导出 db 格式"闭环。
4. **Qt 入口收敛确认**：tkinter 已删（P0）；唯一 Qt6 入口为 **PySide6**（官方 LGPL 绑定），不迁移 PyQt6（无收益且引入授权负担）。
