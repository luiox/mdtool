# mdtool 知识库规范

> 正式规范（v1）。配套：`docs/定位与架构分析.md`（决策依据）、`markdown_util/图片和附件管理规范.md`（媒体服务器细节）。
> 本文是"知识库"层面的规范：目录布局、链接分层、双模式边界、导出与手机端约束。

## 1. 知识库 = 一个根目录

知识库（KB）是一个目录树，**目录是唯一真相源**（散装模式，规范格式）：

```
<kb-root>/
├── notes/                 # 笔记 .md，允许任意子目录
├── images/                # 图片，扁平（image-YYYYMMDDHHMMSSnnn.*，沿用现状命名）
├── assets/                # 附件，扁平（YYYYMMDDHHMMSSnnn.*）
└── meta.db                # 媒体元信息（原始名/size/mime/上传时间）
```

- 整个 `<kb-root>` 可整体同步（手机端 / 备份 / 迁移）。
- 桌面端"选择项目根目录"= 选择 `<kb-root>`；本地媒体服务器 media_root = `<kb-root>`。
- Typora 打开 `<kb-root>/notes` 编辑；`typora-uploader` 上传进 `<kb-root>/images`。

## 2. 链接分层模型

**问题**：现状把 `http://127.0.0.1:8765/...` 写死进笔记，同一份笔记只能在本机渲染。

**原则：存储与渲染解耦。** 三个层次：

| 层 | 形式 | 谁使用 |
| --- | --- | --- |
| 权威标识 | `/images/image-xxx.png`、`/assets/xxx.pdf`（即 URL 的 path） | 一切解析的起点 |
| 存储形式 | 完整 URL（host 默认 `127.0.0.1:8765`，可配置） | 笔记正文；**与现状兼容，零存量迁移** |
| 渲染形式 | 按目标环境改写（见矩阵） | 导出 / 手机 / 未来 LAN |

**任何消费方不得直接使用存储 URL，必须经 resolver 改写。**

### 2.1 解析矩阵（resolver 的职责）

| 消费方 | 规则 | 示例 |
| --- | --- | --- |
| Typora / 桌面编辑 | 原样保留 | `http://127.0.0.1:8765/images/xxx.png` |
| 桌面导出 zip | → zip 内相对路径 | `assets/images-xxx.png`（见 §5） |
| 手机端（同步文件 + 本地服务器） | → app 本地服务器地址 | `http://127.0.0.1:<app-port>/images/xxx.png` |
| 未来：LAN 直连 | → `http://<lan-ip>:8765/...` | 前缀替换即可 |

### 2.2 resolver 接口（两端实现同一语义）

```
parse(url)                    # 识别媒体 URL → (category, timestamp_name) 或 None
rewrite(url, target)          # 按目标环境改写；未知/非媒体 URL 原样返回
  target ∈ {desktop, zip, phone, lan(base_url)}
```

- **识别规则**：`http://<host>:<port>/images/<name>`、`/assets/<name>`，host/port 来自配置（默认 127.0.0.1:8765）。
- **改写规则**：仅替换 URL 前缀/结构，**name 与 alt 文本永不改动**。
- **降级**：解析失败（非本媒体 URL，如外链）→ 原样透传，绝不破坏笔记。
- 桌面端 Python 实现 `markdown_util/link_resolver.py`；手机端 Kotlin 实现同一语义（几十行）。

### 2.3 否决方案（记录在案）

- ~~存储改相对路径~~（`images/xxx.png`，Obsidian 风格）：笔记在 `notes/` 任意深度时相对路径需按深度计算，移动笔记即断链，且需全量迁移存量。否决为默认；保留为远期可选项。

## 3. 双模式边界

| | 散装（文件）模式 | db 容器（"内存态"）模式 |
| --- | --- | --- |
| 真相源 | `<kb-root>` 目录树 | `notes.db`（正文）+ 媒体仍走 `<kb-root>` 图床 |
| 磁盘角色 | 持久存储 | 仅临时落地（默认系统 temp，可配置 RAM 盘） |
| 编辑方式 | Typora 直开文件夹 | 导出到落地目录 → Typora 编辑 → watchdog 回写 |
| 适用场景 | 日常、同步、归档 | 不能/不想持久落地 markdown 的环境 |
| 手机端 | ✅ 支持（同步文件夹） | ❌ 不支持 |
| 互转 | 导出为文件夹 / 导入文件夹（现有工具） | |

- 图片/附件在两种模式下都引用 `<kb-root>` 图床 URL，由本地媒体服务器渲染，**db 容器模式无需落地媒体**。
- db 格式同时是桌面端导出格式之一（单篇/多篇/全库）。
- **同一时间只有一个模式在线**（个人使用约定）：db 模式的存在理由是"有时不能/不想把 markdown 散装落在磁盘"，并非与散装并行使用。两种源互不同步、也无需同步；桌面 UI（笔记库页）据此只呈现当前模式的一棵树。

## 4. 手机端（安卓，v1）约束

- **形态**：原生 app + 内置本地 Web 服务器 + WebView 渲染；只读。
- **数据来源**：`<kb-root>` 目录整体同步到手机（同步工具待定：Syncthing / WebDAV / 网盘）。
- **能力**：目录浏览、笔记渲染（md→HTML，flexmark）、图片/附件加载（app 本地服务器，附件按 meta.db 回传原始名）、全文搜索（v1 遍历匹配，预留 FTS5 trigram）、离线可用。
- **明确不做**：编辑、上传、db 容器读取、连接 PC 流式访问。

## 5. 导出规范（zip）

- **结构**：zip 根 = 单篇 `.md`（现状；多篇/全库导出列为待办）+ `images/` + `assets/` 平铺。
- **链接改写**：媒体 URL → zip 内相对路径（`images/<name>` / `assets/<name>`，resolver `zip` 目标）；相对路径旧链接 → `assets/<basename>`；外链与找不到的文件原样保留并告警。
- **zip 内文件名**：保留时间戳名（天然无冲突）；附件原始名回传由服务器 `Content-Disposition` 负责，zip 场景不重命名。
- **导出类型**：单篇（已实现）/ 多篇、全库（待办）；db 格式导出保留。

## 6. 与现状的差异与迁移

| 现状 | 规范后 | 迁移动作 |
| --- | --- | --- |
| 笔记散落任意目录 + 独立媒体根 | 统一 `<kb-root>`（notes/ + images/ + assets/） | 媒体根设为 KB 根；笔记迁入 notes/；链接批量改写（复用 migrate 能力） |
| 链接硬编码 127.0.0.1:8765 散落各处正则处理 | resolver 统一解析/改写 | 导出/手机消费方改走 resolver |
| zip 导出不改写链接（图挂） | 按 §5 改写 | P1 修复 |
| db 容器 = 存储模式之一 | 内存态工作模式 + 导出格式 | 行为不变，明确边界与落地目录可配置 |

## 7. 未决事项

- 同步工具选型（Syncthing / WebDAV / 网盘）
- 手机端搜索策略（遍历匹配 vs FTS5 trigram）
- meta.db 是否必须随 KB 根同步（附件原始名依赖）
- 桌面端是否保留 notes.db 作搜索索引缓存
